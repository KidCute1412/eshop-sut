## AI Gap Summary

- Initial AI output was broad and generally covered the required FR-02 functional, shared-form, API, DT, and BVA areas.
- Human review improved the suite mainly by reducing duplicate coverage, merging active-lockout DT cases into stronger BVA cases, and removing API duration BVA cases from the merged file.
- Current `test-cases.md` contains 31 executed cases rather than the initial 38 designed cases.
- No human-added test case ID is evident in the current reviewed file.
- No genuine AI-missed test case is identified from the current reviewed artifacts.
- Six confirmed bugs were found during execution, but each was exposed by an existing AI-generated and human-approved case, so they are runtime discoveries rather than AI-missed bugs.

## Lessons Learned

- BVA cases can subsume broader domain cases when they exercise the same observable state with better boundary traceability.
- Shared-form UI conformance checks should remain separate from functional login outcomes because controls, markers, masking, and message placement can fail independently.
- Timing-related lockout tests need careful wording: expected results should assert public behaviour at documented points without inventing timer internals or hidden precision.
- AI gap analysis should distinguish over-generation from missed coverage. In FR-02, the main AI design issue was duplicate/over-broad coverage, not missing normative partitions.
- Runtime failures exposed by AI-generated tests are evidence of useful test design, not evidence that AI missed those bugs.
