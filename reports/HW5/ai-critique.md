# AI Critique

The most important AI limitation in this HW05 work was that the first draft treated performance testing as a generic sequence of HTTP requests and did not fully respect the SUT's stateful behavior. The workflow cannot call cart and checkout correctly unless the JWT token is extracted after login and reused in the Authorization header. Without that correction, many virtual users would produce 401 responses and the throughput numbers would be meaningless. The AI also missed several concrete scripting details: Login needed `Content-Type: application/json`, the Authorization header had to use `Bearer ${token}` instead of an escaped literal value, and Checkout needed valid JSON with a computed `total_amount`.

Another limitation was workload design. The initial stress draft used a finite `80 users / 120s / 5 loops` configuration, which behaved more like a larger load test than sustained stress. I changed it to continuous looping with higher pressure, then verified the results from raw JTL logs. The actual runs showed 0 failed samples, so I did not invent a bug report. However, the logs still showed Checkout as the slowest step, especially in Spike and Endurance / Soak. The main lesson is that AI is useful for structuring the experiment, but performance conclusions must come from real logs, resource screenshots, and human review of metric interpretation.
