## AI Gap Summary

- No human-added or removed FR-07 test case ID was identified; the current suite retains 20 AI-generated cases.
- The largest AI gap was not missing coverage, but inaccurate execution/setup and overly broad runtime classification.
- Human review corrected requirement traceability by separating supporting setup quantity into `FR07-SETUP01`.
- Human review corrected BVA naming and scope from cart requirement BVA to setup quantity BVA.
- Current Pass/Fail counts changed from preserved AI output `4 Pass / 16 Fail` to current `6 Pass / 14 Fail`.
- `FR07-BVA-002` and `FR07-BVA-003` were corrected from Fail to Pass.
- Current bug reporting improved from 8 broad candidate groups to 10 confirmed, requirement-specific bug records.
- The current failure set is still produced by AI-generated tests, so the bugs are runtime discoveries, not AI-missed test cases.

## Lessons Learned

- Before marking dependent UI cases as Fail, confirm that the setup state is visible through the same public UI surface being tested.
- Public API setup may not be equivalent to UI cart setup unless the test basis or observed public behaviour proves the state is shared.
- Separate setup requirements from feature requirements to keep rule IDs stable and traceable.
- When a broad dependency appears to fail, avoid collapsing all downstream cases into one root cause until each observable requirement is checked.
- Valid boundary values should be re-executed independently when a setup issue may have produced false failures.
- A bug report should group by documented requirement and observable contradiction, not by an assumed root cause.
