FR-05: Product listing and search

Objective
Use domain testing and boundary value analysis to derive black-box test cases for the product listing and search behavior described in the functional requirements.

Inputs and observable outputs
- Input: search keyword entered by the user.
- Output: displayed product grid, loading state, empty state, safe rendering of search text, and page heading structure.

Equivalence classes identified
- EC01: No search term / initial page load -> the full product list should be shown in grid format.
- EC02: Search term matches an existing product name -> only matching products should be shown.
- EC03: Search term matches no product -> an empty-state message should be shown.
- EC04: Search term contains HTML/script-like characters -> the value should be displayed as text safely without executing HTML.
- EC05: Blank or whitespace-only input -> the default full list should be restored.
- EC06: Products are still loading -> a loading indicator should be visible.
- EC07: Page heading structure -> the page should contain exactly one h1.

Boundary value analysis
- The search input has a natural boundary at the empty/blank state. This is the smallest meaningful input and should be tested explicitly.
- The result-set boundary is also important: one matching result, zero matches, and a full list are all distinct behaviors and should be tested.
- The safe-rendering boundary is the presence of special characters that could be interpreted as HTML; this is tested separately because it changes the expected output.

Why these classes are sufficient
Each class represents a distinct expected behavior from the black-box perspective. Testing one representative value from each class gives good coverage without unnecessary redundancy.
