# AI Critique (200-300 words)

The clearest place the AI got something wrong was applying a generically "correct" Playwright pattern without checking it against this specific SUT. It reached for `test.describe.configure({ mode: 'serial' })` because the tests share mutable backend state. The diagnosis was right, but the fix was wrong. Playwright serial mode skips every remaining test in the block after the first failure, which is harmful here because several tests intentionally assert the specification against known buggy behavior. The first genuine coupon defect caused many other tests to be skipped, hiding useful results.

A second mistake was copying `reuseExistingServer: !process.env.CI` from a common Playwright template. That pattern is usually convenient, but this backend resets and reseeds its SQLite database on boot. Reusing an already-running server across browser runs carried mutated state, such as coupon usage counts and order totals, from Chromium into Firefox/WebKit. The result was no longer a fair multi-browser comparison.

Both failures came from treating automation infrastructure as boilerplate. The AI reasoned well about individual assertions, but it did not fully reason about the side effects of configuration choices in this SUT. The lesson I learned is that AI-generated test infrastructure must be reviewed and executed just as carefully as test logic. A locator, wait, or config option that looks idiomatic can still invalidate the evidence if it conflicts with the real application state model.
